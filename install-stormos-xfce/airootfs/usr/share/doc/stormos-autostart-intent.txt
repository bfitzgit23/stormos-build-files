StormOS autostart intent
========================

stormos-welcome
---------------
- Auto-started by the desktop environment via:
    /etc/xdg/autostart/stormos-welcome.desktop
- Liveuser copy (first login):
    /etc/skel/.config/autostart/stormos-welcome.desktop
- Purpose: welcome/first-boot helper on fresh installs and on the live media.
- Launch method: DE autostart, not from .zlogin or automated_script.sh.
- Exec: /usr/local/bin/stormos-welcome

abif (CLI installer)
---------------------
- Autostart desktop file (disabled by default):
    /etc/xdg/autostart/abif.desktop
- Liveuser autostart copy (first login):
    /etc/skel/.config/autostart/abif.desktop
- Purpose: provide a desktop entry for the StormOS CLI installer so the
  user can launch it from the application menu or enable it for autostart.
- Exec: alacritty --class 'alacritty-float,alacritty-float' --config-file
  /abif-master/alacritty.toml --title 'StormOS Installer (CLI)' -e sudo
  /abif-master/abif
- Source in this tree:
    /abif-master/abif.desktop
- Autostart default: disabled (Hidden=true).
  This entry is intentionally not launched automatically on login, so the
  user can choose when to start the installer rather than having Calamares/
  the installer appear on every boot.
- To enable autostart, change Hidden=true to Hidden=false in one of:
    /etc/xdg/autostart/abif.desktop
    ~/.config/autostart/abif.desktop

Application menu entry
----------------------
- Menu-only installer entry (not an autostart entry):
    /usr/share/applications/stormos-installer-cli.desktop
- Purpose: show the CLI installer in the application menu even though
  autostart stays off.
- Hidden=false by default, but it is not placed under /etc/xdg/autostart
  or ~/.config/autostart, so it does not launch on login.

Optional removal after install
-------------------------------
- The postinstall flow can remove the installer shortcut from the installed
  system if the user picks that option.
- Trigger it by setting this environment variable before postinstall runs:
    CALAMARES_REMOVE_INSTALLER_DESKTOP=1
- When enabled, postinstall removes installer-related desktop entries from:
    /usr/share/applications/
  including entries such as:
    stormos-installer-cli.desktop
    abif.desktop
    install-stormos-cli.desktop
    install-stormos-desktop.desktop
    welcome.desktop
  The CLI installer binary and /abif-master are intentionally not removed
  by this flag unless a separate uninstall step is implemented.

Automated installer behavior notes
-----------------------------------
- The live media and installed system are configured so the installer is
  not forced to run automatically on boot.
- If Calamares is used for installation, the live/installed setup should
  not auto-start the installer on every login. The desktop entry above is
  a user-launched entry, not an auto-install flow.
- If a previous install image or postinstall step enabled an autostart
  installer entry, remove or disable it by setting Hidden=true, or by
  removing the file from:
    /etc/xdg/autostart/
    ~/.config/autostart/

Autostart behavior notes
------------------------
- Both desktop files use:
    Hidden=false
    X-GNOME-Autostart-enabled=true
    X-KDE-autostart=true
- This is intentional so the entries are honored by XFCE, KDE, and the
  liveuser session.

Installer behavior notes
------------------------
- The postinstall flow may recreate /etc/xdg/autostart/stormos-welcome.desktop
  on the installed system if it is missing.
- Installer utilities in sysconfig.py include a defensive guard that should
  not delete or overwrite the welcome autostart files.
- The Calamares branding notes in this tree document the installer shortcut
  behavior and the postinstall removal trigger path. They also document a
  Calamares module trigger path so the same installer shortcut removal can
  be requested directly from the Calamares session itself, not only from
  sysconfig.
- The sysconfig GUI includes an "Installer Shortcuts" tab that can request
  installer-shortcut removal on the installed system and can be used to pick
  which installer autostart entry is enabled.
- That installer picker now shows the installer autostart entry and the
  matching installer menu entry side by side. If the user disables every
  installer autostart entry, the picker also hides the matching menu-only
  installer entry so the two sides stay consistent.
- The postinstall flow has a matching consistency check: if it disables every
  known installer autostart entry during installation, it also hides the
  matching installer menu entry from /usr/share/applications so the installed
  system does not keep a visible menu entry whose autostart counterpart is gone.
